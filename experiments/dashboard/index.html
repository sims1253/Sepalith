Standing decisions & rules

  • Suffix-completion convention everywhere: predict ONLY what comes after the cursor (user decision; finish-block re-emission retired).
  • Dropout conditioning is the production config — justified by robustness to prompt population, not type signal (ablation showed none).
  • Telemetry: local collection always, upload never — until an explicit opt-in (off by default).
  • Eval battery: acceptance counters (extension) > validator-exact scenario families + calibrated judge + intent assertions > line-F1 midtyping (composition-blind, 4 datapoints).
  • Effort is never a blocker; llama.cpp support is deployment evidence, not selection criteria. Wide architecture space gets a genuine pass.
  • Quota discipline: max 6-8 concurrent zai consumers; Gemini (agy) and Opus 4.6 (separate quota) for free-tier generation; Opus reserved for high-judgment tasks.
  • Ops: llama-server evals CPU-only; readiness via POST /v1/completions (never /health); kill by tracked PID/port only; GPU jobs strictly sequential (flock, not memory polls — the 03:20 incident).
