# Independent daily LAN lifecycle review

Decision: reject v1 for live lifecycle admission; v2 has no remaining concrete launch blocker identified by this bounded CPU/source review. Root still owns deployment and live admission.

V1 had two concrete lifecycle problems. Its serving loop required the RTX ledger owner to remain None, conflicting with recording the live daily owner. Its bare bind probes omitted SO_REUSEADDR, which can reject immediate restart while an old connection remains in TIME_WAIT even after the listener exits. The second finding was a source comparison with the accepted DEV controller's earlier fix; this reviewer opened no sockets.

Frozen v2 resolves those findings narrowly. Under the existing stable cuda0.lock, LedgerLease replaces only the exact free RTX row with the session UUID and supervisor identity. Owned.guard checks that same row during readiness and serving. Cleanup releases it only after all owned children exit and only when the row still matches. Unrelated rows are preserved; a changed competing row stays untouched. Artifact preflight is now inside the cleanup path. free_port sets SO_REUSEADDR and retains active-listener rejection. The author reports both socket regressions passed; this reviewer inspected them but did not run them under the no-network scope.

Independent validation of frozen v2: 11 original lifecycle tests, eight real temporary-ledger tests and one additional synthetic success-path test passed (20/20). The success-path test calls the actual run_session function and exercises five launch argv constructions: native, gateway, binding upload, reverse tunnel and notebook probe. It verifies source pins/admission, binding upload bytes, readiness predicates, completed-child bookkeeping, one serving-loop iteration and terminal cleanup including the new ledger lease. Process creation, HTTP, socket binding and native artifact metadata are synthetic boundaries; this is not live CUDA, SSH, editor or model proof. The preserved three pure gateway test groups passed against v1, and all gateway/helper/VSIX bytes are identical in v2. Every source-manifest entry was checked before and after replay.

The actual native argv retains selected theta0 Q8, loopback 18403, context 4096, batch/ubatch 256, one slot, six compute threads, two HTTP threads and 99 GPU layers; environment sets GraphOpt=0. Gateway listens on desktop loopback 18423. SSH uses a remote loopback forward from notebook 18403 to desktop 18423, BatchMode, strict known-host checks, forward-failure rejection and keepalives. The 4,577-byte binding upload is closed before its bounded SSH wait. The daily gateway patch changes only the explicit maximum session duration; default duration and identity/request/cancel/queue implementations remain unchanged. No successful-path undefined name or unintended persistent wait was found.

The exact VSIX is b8268083aabc72c02623ee07f8b75bb932fd4aaec15e6972724bca9330be74b1. Its actual package exposes the documented Start server and Stop server commands. Notebook settings select the application-scoped binding path, CUDA, port 18403/context 4096, request timeout 5,000 ms, debounce 1,500 ms, scope off, debug off, auto-start off and post-accept cooldown on. The receiver checks the selected full manifest and atomically replaces a fresh UUID binding. The remote connection verifies runtime/props and each instance header. Extension stop disconnects only; restarting the daily process needs the documented extension stop/start to bind the new UUID. ready.json correctly leaves extension handshake pending.

The live smoke remains bounded and root-controlled: run two consecutive sessions, each with an outer 180-second bound and at least 30 seconds for cleanup. In session one, require exact root deployment pins, a daily-owned ledger row, ready.json, actual notebook Remote CUDA handshake, and one synthetic/TRAIN-only suggestion. Stop via the launcher, wait for terminal.json and verify all recorded children absent, ledger released and global lock reacquirable. Immediately start session two with a new UUID; require the same model/server/profile and another actual extension stop/start handshake. Stop and verify release again. Record actual argv, instance headers, binding hashes, logs and terminal evidence. A stop command returning does not itself prove cleanup; wait for the terminal and recorded identities. Do not promote from this CPU receipt or from the notebook HTTP probe alone.

This review did not edit the launch packets or campaign ledger, read model weights, inspect final content, open network sockets, invoke SSH or start CUDA/native servers. Temporary subprocesses and ledger fixtures were confined to the review directory. Multi-hour stability, actual SSH installation/placement, gateway/model quality and latency on the daily bytes remain outside this short lifecycle review.
