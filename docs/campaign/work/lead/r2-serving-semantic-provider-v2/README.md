# Serving semantic provider v2

This packet is an isolated production-integration candidate. Shared production source is unchanged. It copies the current extension source, applies the previously reviewed `context_select` typed-evidence seam, adds a conservative prediction-time R semantic provider, and changes the copied `extension.ts` primary request path to call `buildPrimaryPromptContext` before `renderPrompt`. The provider follows the existing `scopeContext` configuration gate; disabling scope context preserves the old path.

At a zero-width blank line in an unsaved `.R` document, the provider derives the immediately following top-level named function. The blank line through the complete function is the required contiguous source span. It scans top-level braced function definitions, resolves local function dependencies recursively in lexical order, gives local definitions precedence over base names, and emits omitted helpers as required `EvidenceCandidate` records. Candidate content, line span, source version, excerpt hash, and full-document hash-bearing identity all come from the same current `getText()` snapshot.

`buildPrimaryPromptContext` verifies URI, version, and complete document hash before and after context selection. `selectEvidence` then verifies each required excerpt and budget. LF and CRLF retain the production full-document replacement hash and global range while helper records use canonical logical-line content. A changed version or changed bytes invalidates the provider result.

The provider never evaluates R and never receives target text or an expected output. Its bounded grammar supports top-level `name <- function(...) { ... }` and `name = function(...) { ... }` definitions. Unknown call heads or free identifiers, duplicate local definitions, nested-only helpers, malformed or unsupported definitions, mixed EOL, and evidence over budget return named unresolved results. The copied extension logs unresolved reasons and falls back to its existing context.

The v2 scanner additionally inspects function-valued arguments to `do.call`, `lapply`, `sapply`, `vapply`, `Map`, and `Reduce`. Exact string literals resolve through the same local-definition closure and become required evidence when cropped from the source window. Bare symbols resolve only when they are a known local definition or base call. A formal, computed expression, missing argument, or missing literal target returns a named unresolved result. The scanner locates the outer call from masked code, then reads the argument from the identical raw snapshot, so strings or calls in comments are not treated as dependencies.

The executable slice is intentionally narrower than analyzer v6. NSE resolution and unqualified package namespace resolution remain unresolved because the current extension has no authoritative package parser or namespace snapshot. Helper parity is demonstrated on synthetic R controls through the actual copied `extension.ts` integration seam. An authorized actual TRAIN row demonstrates prediction-time target-span derivation, global identity, and production context construction, but that row has no required helpers. Corpus-wide parity and training admission remain pending root review and a representative accepted helper-row comparison.

The local test suite passes 74 checks, strict TypeScript compilation, and an esbuild of copied `extension.ts`. The inherited notebook latency measurement remains v1 evidence; v2 has not been benchmarked on the notebook.
