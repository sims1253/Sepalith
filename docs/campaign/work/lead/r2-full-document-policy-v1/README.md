# Prediction-time full-document policy preparation

This review-only packet selects context without target or gold information. It first renders the complete current editor document through the production selector and renderer, then asks the managed llama.cpp `/tokenize` endpoint for the exact prompt-token count. Full-document mode is selected only when `1 BOS + prompt tokens + 1024 generation reserve <= context size`. When it does not fit, the existing semantic complete-span provider is used if it is supported and its independently tokenized prompt fits. Otherwise the request is held with a named reason.

On the frozen 49 analyzer-supported TRAIN rows, the 16K profile chooses 42 full documents, five complete-span fallbacks, and two holds. It covers 47/49 rows and 6/8 helper rows. The 32K profile chooses 47 full documents and two complete-span fallbacks, covering 49/49 and 8/8 helper rows. The two 16K holds are helper-dependent rows whose full documents do not fit and whose current provider evidence is unresolved. No target length participates in these decisions; policy fixtures contain no target or gold field.

Compared on the 30 rows already supported by the current provider at its production 6,000 UTF-16-unit source budget, full-document prompts add a median 845 tokens (1.447x). The full-document branch preserves renderer order, complete pre-edit buffer identity, global zero-width replacement position, and UTF-8/UTF-16 geometry. Five fixtures contain non-ASCII text and pass the same hash and range checks. The frozen census contains LF files; CRLF behavior remains covered by the inherited production selector tests rather than this specific 49-row cohort.

`source/extension.ts` is an isolated integration candidate only. It deliberately uses the existing validated `NativeCampaignClient.tokenize`, so the token count comes from the active model tokenizer rather than a length estimate. The current candidate tokenizes the selected prompt again inside `complete`; root should either accept that request overhead or add a reviewed pretokenized completion interface. Root must also bind a 16K or 32K managed runtime profile and the 1,024-token reserve before application. No production file or training corpus was changed.
